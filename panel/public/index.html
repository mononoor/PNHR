Network tuning

What is this and why?

Linux is tuned by default for regular web traffic, not for VPN. For a proxy this means: slow TCP on high latency (NaiveProxy) and UDP packet loss under high traffic (Hysteria2). This page once applies a set of sysctl parameters that removes these limitations. You don't need to change values manually — they are chosen by Hysteria2/Caddy developers and tested in practice.

  • BBR (net.ipv4.tcp_congestion_control=bbr) — modern congestion control algorithm from Google. Gives 2–10 times higher throughput on TCP connections with packet loss (especially when the client is far from the server). Replaces old cubic. Requires kernel ≥ 4.9 (Ubuntu 20.04+ — OK).
  • fq (net.core.default_qdisc=fq) — fair queuing discipline, required for BBR to work properly. Without it BBR works but worse.
  • UDP buffers 16 MB (net.core.rmem_max/wmem_max=16777216) — Hysteria2 at high speeds (>100 Mbps) writes to the socket in large chunks. The default 212 KB buffer leads to losses and speed drops by several times. Hysteria itself warns about this at startup if the buffer is small.
  • TCP Fast Open (net.ipv4.tcp_fastopen=3) — speeds up repeated NaiveProxy connections to the same server (by ~1 RTT).
  • conntrack 1M — raises the limit of concurrent connections (for 100+ users).

Parameters are saved in /etc/sysctl.d/99-rixxx-tune.conf and applied immediately, and also automatically after reboot. To revert: rm /etc/sysctl.d/99-rixxx-tune.conf && sysctl --system.

Bypass — direct traffic

⚠️ Feature under testing

Bypass is under active testing. Before using in production, be sure to test on your own client: that the required sites open directly, and the rest of the traffic continues through the VPN. If something doesn't work as expected — roll back with the «Clear» button below and report to the author on Telegram.

Why is this needed

Some sites (Russian banks, government services, marketplaces) block foreign IPs. If all traffic goes through a VPN abroad — these sites won't open. The solution is to send traffic to such sites directly, bypassing the VPN. This is called split tunneling / bypass.

  • Hysteria2 (UDP) supports server-side bypass via ACL — works automatically for all clients, no configuration needed on the client.
  • NaiveProxy (TCP via Caddy forward_proxy) does not support server ACL. For Naive, bypass is configured only on the client (Happ/Karing/v2rayN — all support it). Ready-made lists are given in the instructions below.

After enabling bypass it is applied immediately — Hysteria2 restarts with the new ACL.

If Hy2 is running but the client cannot connect:

  • Logs show suppressing panic for copyResponse / H3_GENERAL_PROTOCOL_ERROR / timeout: no recent network activity — these are masquerade responses to client requests that did NOT pass Hy2 authentication. Means the client is connecting with the wrong password or wrong link.
  • Check the link: format hysteria2://PASSWORD@DOMAIN:443?sni=DOMAIN#name. For userpass-auth password = username:password.
  • Cert invalid — the client rejects the Caddy cert. In the diagnostics above check that the cert file exists and is accessible (perms 644).
  • Provider firewall blocks UDP/443 on the client side — try mobile internet or VPN via another region.

CLI tools on the server:

  • Check the entire installation state (version, services, TLS, ports, masquerade, access mode): bash update.sh --status — works without root, safe to run at any time.
  • Recover a broken installation (regenerate Caddyfile and Hysteria config from config.json, auto-backup in /etc/rixxx-panel/backups/, validation and rollback on error): sudo bash update.sh --repair. Before running it is useful to do sudo bash update.sh --repair --dry-run — shows what will be done without making changes.
  • Apply cumulative patches (without reinstall): sudo bash update.sh. Users, domains and certificates are kept.

If Hy2 does not start at all:

  • UDP/443 is occupied by Caddy (HTTP/3). Solution: in /etc/caddy/Caddyfile in the global block {} there should be servers { protocols h1 h2 }, then systemctl reload caddy && systemctl restart hysteria-server.
  • No TLS certificate. Caddy issues it on first request — make sure the domain's A record points to this server and port 80 is reachable from outside.
  • Binary for a different architecture — check on the Dashboard.
  • UFW blocks UDP/443 — run: ufw allow 443/udp && ufw reload.
